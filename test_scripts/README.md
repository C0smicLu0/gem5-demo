# test_scripts

This directory contains helper scripts for building, running, and analyzing `gem5-demo` GPU workloads.

## Files

- `build_gem5_vega_x86.sh`: Build `build/VEGA_X86/gem5.opt` in Docker.
- `enter_docker.sh`: Open an interactive Docker shell with repo mounted at `/gem5`.
- `gem5_test.sh`: Low-level runner with `list | test | analyze | check` subcommands.
- `gem5_workload_runner.sh`: Workload-oriented wrapper with `list | run | analyze | check | all`.
- `gem5_workloads.json`: Workload and argument config.
- `analyze_log.py`: Parse `lat_run_out/seq_lat_stats_*.txt` and generate summaries.

## Path Behavior

Scripts are portable and do not hardcode usernames:

- Repo root is auto-detected from script location.
- `gem5_workload_runner.sh` defaults:
  - config: `test_scripts/gem5_workloads.json`
  - test script: `test_scripts/gem5_test.sh`
- `gem5_workloads.json` uses:
  - `"base_run_root": "tests/testing-results"`
  - Relative paths are resolved against repo root.

You can still override defaults with env vars:

- `GEM5_WORKLOAD_CONFIG`
- `GEM5_TEST_SH`
- `GEM5_ROOT` (for `enter_docker.sh` / build script)
- `DOCKER_IMAGE`

## Quick Start

From repo root (`gem5-demo`):

```bash
chmod +x test_scripts/*.sh
```

Build:

```bash
test_scripts/build_gem5_vega_x86.sh
```

List workloads:

```bash
test_scripts/gem5_workload_runner.sh list
```

Run one workload:

```bash
test_scripts/gem5_workload_runner.sh run square
```

Run + analyze + check:

```bash
test_scripts/gem5_workload_runner.sh all square
```

Manual flow with `gem5_test.sh`:

```bash
test_scripts/gem5_test.sh test --run-dir tests/testing-results/manual-run
test_scripts/gem5_test.sh analyze tests/testing-results/manual-run
test_scripts/gem5_test.sh check tests/testing-results/manual-run 100 150
```

## Output

Each run directory typically contains:

- `simout`, `stats.txt`, other gem5 outputs
- `lat_run_out/seq_lat_stats_*.txt` (generated by Sequencer latency dump callback)
- `analyze.md`, `analyze.json` (from `analyze_log.py`)
